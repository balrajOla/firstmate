# Prompt for the installation agent on my existing machine

Use the following prompt in a local Codex or Claude Code session with filesystem and terminal access. The session must run on the machine that currently has Olympus.

---

Replace my customized Olympus installation with Assistant Workbench from `https://github.com/balrajOla/firstmate`, branch `codex/assistant-workbench`. Resolve and record the exact commit before installing. Read its README, feature register, compatibility matrix, migration instructions and verification report first.

My final active setup must have no Olympus runtime, scheduler, launcher, service or terminal include. Preserve my project repositories, local changes, untracked/ignored files, Git history, credentials, documents, prompt history and authorized schedules. A private recovery archive is allowed; it must not be an active dependency.

Do the work, not just describe a plan:

1. Inspect this machine, existing Olympus checkout/prefix, running services, terminal configuration, official Claude/Codex installations and authentication, and any custom installation paths. Locate the exact old service definitions and executable paths. Do not print secrets or scan unrelated personal folders. Determine which local modifications provide behavior I still need.
2. Create a verified private backup outside the old roots, including Git bundles and the complete working copies. Test restoration into a separate location. Record every local customization and how the replacement preserves, ports or deliberately retires it. Preserve project directories separately from disposable software paths.
3. Install the pinned replacement into a fresh prefix and fresh state directory. It must not import or run Olympus code. Set up the pinned Paperclip coordinator, official harness profiles and selected context/writing integrations. Use my existing official CLI sign-in when I have no API keys. Never extract subscription tokens, invent a provider bridge, add a paid fallback or mark a missing integration as available. If a real login is needed, let me complete it in the official tool and continue afterward.
4. Install the official WezTerm release for this machine, record its version, and integrate the local Workbench module while preserving my theme, key bindings and unrelated plugins. Inspect the actual GUI. Do not equate a headless Textual test with a WezTerm desktop test.
5. Run the repository tests and the installed-artifact tests, then actual end-to-end journeys: concurrent prompts; explicit and ambiguous project routing; grouping and withdrawal of one demand; amendments while work is running; two genuine parallel agents exchanging evidence; review and persistent outcomes; scoped memory recall in a fresh process; source revocation; five real fresh-context handoffs; cumulative limits; cancellation with stop evidence; report export; terminal resize/reconnect; service restart; and backup/restore. Exercise Open Notebook and GPT Researcher in every profile claimed as supported. Record real commands, versions, exits, artifacts and screenshots. Do not use fixtures as evidence of real agent execution.
6. Compare observed behavior with every applicable PF feature in `docs/FEATURES.md`. Fix implementation/integration problems within this project, add meaningful regression tests, and commit fixes to the repository. Keep missing capabilities and blocked tests explicit. The current branch is experimental: a complete full-profile replacement is not authorized by a green unit-test run alone.
7. Once the replacement's required target-machine gates pass, stop only the verified legacy Olympus services and owned processes, remove exact Olympus-owned shared-config lines, generate the cutover certificate and retire the backed-up application paths. Use the migration commands and ownership receipts; do not run broad deletion commands against my home, credential directories or project roots. Remove obsolete owned launchers, service definitions and active plugin references so Olympus cannot restart.
8. Launch the replacement from its installed command and WezTerm, verify that it has no dependency on the old installation, and repeat the core prompt-to-outcome and restart journeys. Give me the exact installed commit, feature/test results, unresolved limits, backup/restore location and the commands I will use daily.

Continue autonomously for actions covered above. Ask only for missing account interaction, an unavailable required environment, or a consequential ambiguity that the machine and repository cannot resolve. If a required gate remains blocked, keep the old installation recoverable, explain the blocker and do not claim that replacement or full verification is complete.
